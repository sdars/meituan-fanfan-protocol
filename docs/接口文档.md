## 2. 通用请求头/签名

所有请求在发出前经 `@mtfe/weapp-safety-request` → `jsguard.signWithSiua(options)` 注入:

- `header.mtgsig` : JSON 字符串 (见 `算法原理.md`)
- `@mtfe/weapp-safety-request` 的 `addCommonParams` 层 (`utils/params.js` +
  `constants/common.js`) 在 **签名之前** 就把以下参数并入 url/header,
  因此它们会被签名覆盖:
  - **url query** (`PARAMS_POS.url`): `yodaReady=wx`, `csecappid=<AppId>`,
    `csecplatform=3`, `csecversionname=<小程序版本>`, `csecversion=1.4.0`
    (`defaultInitParams` 提供 `yodaReady/csecplatform/csecversion`, `params()` 提供
    `csecappid/csecversionname`)
  - **header** (`PARAMS_POS.header`): `token`, `csecuuid`(lxcuid), `csecdpid`,
    `csecuserid`(=userId), `openId`, `openIdCipher`, `eptoken`, `csecepuid`
  - 注入规则: 若 url 已含同名 query 或 header 已含同名键 (不区分大小写),
    则不覆盖; 空值不追加。
- 业务拦截器 (`api/interceptors.js`) 追加:
  - `header.mt-c-token` = 用户 token (addMcToken)
  - `header.deviceid`   = 设备 ID (addDeviceId)
  - `data.lat` / `data.lon` = 经纬度 (addOadParams)
  - `data.xcxVersion`   = 小程序版本 (addAppBaseInfoParams)

### 2.1 openresty WAF (403) 的真实触发条件

直接用 `requests` / `curl` 打业务接口会碰到 `openresty` 的 403
(响应仅 `Server: openresty` + `X-Forbid-Reason: .`)。实测根因分层:

1. **UA 缺失/默认值必 403**。`requests` 默认 UA `python-requests/x.y`
   或完全不带 `User-Agent` 时, **所有** `/wmpact/*` 路径都 403。
   任意正常浏览器/`Mozilla/5.0` UA 即可解锁大部分路径。
   → 本实现 `FanfanClient` 默认带 `DEFAULT_UA`。
2. **空主机头 (Host/SNI) 不同的边缘节点策略不一致**。prod 域
   `offsiteact.meituan.com` 对一子集路径 (`mission/user/list`, `daodian/get_wxlist`,
   `mission/cash/back`, `ge/queryCpsSharePoi`, `wallet/detail`, `generalWallet/*`,
   `ge/queryPoiInfo`, `ads/resource/get`, `rights/mall`, `rights/user/unused/list`,
   `mission/talent/selectpool`, `mission/user/wait/comment/list`, `mission/user/comment/get`,
   `daodian/get_single`, `ge/queryPoiByRecallBiz` 等) 在本环境出口 IP
   (测试机位于**美国 LA**) 下恒定 403——与签名、header、cookie
   无关 (真实 jsguard `signWithSiua` 签名同样 403)。
   这是 **边缘/地域风控策略**, 不是协议问题。
3. **staging 域 `offsiteact.st.meituan.com` 无此限制**, 全部 60 个 `/wmpact/*`
   路径均正常返回业务 JSON (http 200)。因此在当前出口环境下,
   **业务链路的闭合验证走 staging 域**。

> 结论: 签名/注入链路完全正确 (staging 域逐字节通过)。prod 域部分路径的 403
> 是出口 IP 级别的 WAF 拦截, 与纯协议实现无关。换到国内/真机出口
> (or 使用 st 域) 即可解锁全部。

响应处理 (`returnData`): `ret === 999999` 表示登录态失效, 触发重登。

## 6. 受限项

- `code`: 必须由真实微信环境 `wx.login` 获取, 纯协议侧无法凭空生成。
- `device_type` / `sdkVersion` / `utm_medium` 等设备字段: 真机由 `wx.getSystemInfoSync()` 提供;
  纯协议侧使用配置值即可 (服务端不校验设备字段与签名的一致性)。
- `env_flag` (mtgsig 的环境自检位): 真机微信小程序取值需实测确认; devtools 桩环境实测为 `123`,
  本实现 `Signer.env_flag` 默认 `6` (真机微信小程序常见值), 可按环境调整。

## 4. 签到链路 (check/in) 闭合实测 (2026-10-11)

签到**不是**一个独立接口, 而是 **两个接口按顺序** 组成 (前端 `chunk_8` 签到页):

```
[1] fetchActivityList(queryModel=['CHECK_IN'])   POST /wmpact/xcx/activity/list
      -> data.checkIn = {
           missionSecretId: "...",      # 本次签到会话 id (服务端下发)
           isTodayCheckedIn: false,
           daysCheckedIn: 0,
           checkInList: [ {day, status, isCanCheckIn, awardType, awardValue, ...} ... ]
         }
[2] 取 checkInList 里 isCanCheckIn=true 的那一项的 day
[3] fetchSignInInfo(missionSecretId, day)        POST /wmpact/mission/check/in
      body {day, missionSecretId}
      -> {ret:0, data:{awardType:'POINTS', awardValue:100}}
[4] 复查 fetchActivityList -> isTodayCheckedIn=true, daysCheckedIn=1
```

前端函数签名 (`api/index.js`):
```js
fetchSignInInfo = (missionSecretId, day) =>
  request(signIn, {method:'POST', data:{day, missionSecretId}});   // signIn="/wmpact/mission/check/in"
fetchActivityList = (queryModel) =>
  request(activityList, {method:'POST', data:{queryModel}});       // activityList="/wmpact/xcx/activity/list"
```

### 4.1 关键坑: **必须用 prod 域**

两个域返回的 `missionSecretId` **不同**, 且**只有 prod 域的 id 能过 check/in**:

| 域 | fetchActivityList 返回的 missionSecretId | fetchSignInInfo 结果 |
|---|---|---|
| prod `offsiteact.meituan.com` | `100000020241016` | ✅ `ret:0` 成功, 发放 `awardValue:100 POINTS` |
| staging `offsiteact.st.meituan.com` | `155088931689027956401` | ❌ `ret:99` “签到失败，请稍后重试~” |

即: 用 st 域取到的 `missionSecretId` 拿去打 **st 域的 check/in 也失败** (ret 99),
而 prod 域 `fetchActivityList` -> `fetchSignInInfo` **闭环成功**。故签到必须走 prod。

> 这与「业务只读接口 st 域全放行、prod 域部分 403」相反: 签到是**写操作**,
> 服务端在 prod 域做了完整校验, st 域只是影子环境 (missionSecretId 无效)。

### 4.2 实测记录

```
# prod 域, 真实闭环
[1] missionSecretId = 100000020241016  isTodayCheckedIn = False  daysCheckedIn = 0
[2] target day = 1 (award=100 POINTS)
[3] signIn -> {"ret": 0, "msg": "成功", "data": {"awardType": "POINTS", "awardValue": 100}}
[4] after -> isTodayCheckedIn = True  daysCheckedIn = 1
```

`FanfanClient` 已封装:

- `cli.fetch_check_in()` -> `data.checkIn` 字典
- `cli.sign_in()` -> 自动取 `missionSecretId` + 可签到的 `day`, 再打 check/in

见 `examples/sign_in.py`。
